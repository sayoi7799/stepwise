# 答辩要点

## 一句话（电梯陈述，约 20 秒）

> 拾级 Stepwise 是一个给中文学习者的分级阅读流水线。它不翻译，而是先量出你
> 读懂了多少、卡在哪几个词，再挑出只比你现在难一点点的句子给你读——**包括
> 模型给的解释，它也要先过我们自己的可读性审计**，不达标就带着具体的超纲词
> 重新生成。

## 评委最可能质疑的一点：这不是又一个翻译器吗？

这是我们主动要讲清楚的差异，别等评委问。

| 划词翻译 / 双语对照 | 拾级 Stepwise |
| --- | --- |
| 把中文换成英文 | 用中文解释中文，解释本身也控制在你的词汇范围内 |
| 读完只记住英文，中文还是没进去 | 每次读的都是刚好高一点点的中文（i+1） |
| 不知道这本书适不适合我 | 先算覆盖率，直接告诉你「从第几章开始读得动」 |
| 模型说什么就是什么 | 模型的输出要过我们自己的尺子，覆盖率如实显示 |
| 生词卡背面是中英对照 | 背面是它出现的那句话 |

一句话概括：翻译工具解决「让你看懂这一段」，我们解决「让你积累到能看懂下一段」。

## 现场演示（四条命令，建议录屏）

```bash
# 1. 113 个测试，全部离线——不需要网络、不需要 API key
moon test

# 2. 一本书进去，逐章体检表出来
moon run cmd/main -- analyze samples/sample.epub --level 2

# 3. 起本机服务，浏览器里点一段 → 五种解释模式
moon run cmd/main -- serve samples/sample.epub --level 2
#    浏览器打开 http://127.0.0.1:8787/ ，点正文任意一段

# 4. （可选）看质量闸门怎么工作：每次尝试的覆盖率都列出来
moon run cmd/main -- explain 意思 "这句话很有意思。" --pinyin yìsi --word-level 3 --attempts 3
```

第 3 条最值得录：点一段，卡片从段落下面弹出来，上面有一排模式按钮——
**改成简单中文 / 逐词解释 / 语法拆解 / 理解检查 / 英文翻译**，点哪个换哪个。
实测输出（`小明的家很近，走路只要十分钟。`）：

```
【改成简单中文】那个孩子的家不远，走路只要十分钟。
                Xiao Ming's home is very close; it only takes ten minutes to walk there.
                可读性审计：覆盖率 90.9%，仍有超纲词（钟）。

【逐词解释】    只要：只用，不用做别的
                分钟：时间，六十秒是一分钟

【语法拆解】    这句话主要说：小明的家很近。
                "走路只要十分钟"是在说：很近，不用坐车。

【理解检查】    问：小明走路回家要多久？
                答：十分钟。

【英文翻译】    Xiao Ming's home is very close—it's only a ten-minute walk.
```

注意【改成简单中文】最后那行——它在**主动告诉学习者这段改写里还有超纲词**。
这就是我们说的「度量诚实」。

## 三个技术决定（对应验收标准里的「可解释」）

1. **确定性的内核，不确定的外壳。** 分词、覆盖率、难度分档、复习调度、EPUB
   解析都是纯逻辑；唯一不确定的模型调用被压缩成一个 trait，测试里换成脚本化
   假客户端。所以 CI 不需要网络和密钥也能跑完整条流程。
2. **时钟与随机数由调用方传入。** 复习调度不读系统时间，「三个月后的复习计划」
   在测试里一秒就能验证。
3. **审计结果回灌，而不是笼统地说「太难了」。** 审计算得出具体哪几个词超纲，
   重试时点名要求换掉。实测同一句话的覆盖率轨迹从 79.3% 提到 92.3%。

## 评委可能问的问题

**Q：这和沉浸式翻译、划词翻译有什么区别？**
A：它们把中文换成英文，读完你只记住英文。我们输出的是中文——解释、改写、
语法说明全部用中文写，并且**解释本身也要过可读性门槛**。这是产品立场不同，
不是功能多少的问题。

**Q：核心东西是你们自己做的，还是调 API？**
A：模型只负责「把一句话说简单」这一件事。下面是全部自己的代码：双向最大匹配
中文分词、已知词覆盖率、难度分档、i+1 句子挑选、EPUB 解析（容器/OPF 清单/
XHTML 转文本）、SM-2 复习调度、SSE 增量解析、可读性审计与超纲词回灌、
学习版页面生成。第三方库只用在两处：DEFLATE 解压和 HTTP 传输。

**Q：测试怎么保证？**
A：113 个测试全部离线通过。模型调用被抽象成一个 trait，测试用脚本化假客户端，
所以「不达标就重试」这条逻辑也是被测试覆盖的。CI 每次提交都跑。

**Q：数据合规吗？**
A：HSK 3.0 词表来自 ivankra/hsk30（MIT），原始 CSV 与许可证全文随仓库提交在
`data/source/`；本项目代码 Apache-2.0。

**Q：这个 MVP 真的能用吗？**
A：现场跑一遍。四条命令，其中三条不需要任何密钥。

**Q：为什么选 MoonBit？**
A：项目形态是「文本流水线 + 多后端」，确定性内核用 MoonBit 写，天然能同时编到
native 与 wasm-gc；语言自带的 test / snapshot / fmt / coverage 让「可测试、
可复现、可维护」这三点成本很低。生态里也还没有中文分级阅读这一类东西。

## 三个「别的作品很难复制」的点

1. **自己造尺子去量模型。** 不是调 API 拿结果，而是给模型的输出定标准、测它、
   不达标就退回重做。
2. **发现并修正了度量本身的缺陷。** 被解释的词本来就不该算超纲——不排除它，
   任何解释都过不了门槛，度量会一直说谎。
3. **对边界诚实。** 人名「小明」会被判成未收录、覆盖率 90.9% 时如实标注
   还有超纲词。我们不粉饰数字。
