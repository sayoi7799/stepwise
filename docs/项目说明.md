# 拾级 Stepwise —— 一页项目说明

**让外国中文学习爱好者用中文的思维理解中文赚取工具收费钱。**

## 问题

外国人读中文原文时卡在三处：

1. **不知道读什么。** 太难了根本理解不了。
2. **读不懂就查词典。** 拿到一个中英对照，回到原文还是连不起来——
   因为读懂句子靠的是语感，不是词表。
3. **生词背了不会用。** 卡片背面写着英文，离开语境，记住的是对应关系，
   不是这个词怎么用。

现有的工具（浏览器划词翻译、双语对照阅读器）解决看懂的问题
但没有解决「让你积累到能看懂下一段」。结果是读了半年，还是靠翻译活着。

## 做法

**一、先量再读。** 用词表驱动的双向最大匹配把文本切成词，逐词对照学习者的
等级，算出「已知词覆盖率」，再按泛读研究的经验区间分档：低于 90% 读不动，
90%–98% 需要支撑，98% 以上才谈得上顺畅。

**二、挑出刚好难一点点的句子。** 逐句统计生词，一个生词都没有的句子只能
巩固；**一到三个生词的句子最适合精读**；四个以上负担过重。这也就是二语
习得里说的「i + 1」。

**三、用中文解释中文，并且解释本身也要过关。** 这是项目最核心的一个设计，
也是和「套一层翻译 API」最大的区别：模型给出的解释会被送回**我们自己的
分词器和学习者模型**审计——如果解释里的超纲词太多，就带上更严格的约束
重新生成。模型的输出必须先是「学习者读得懂的输入」，才有资格被看见。

这里有两个细节让它不只是「拦截」，而是真正的反馈闭环：审计算得出**具体
哪几个词超纲**，重试时就把这几个词点名要求换掉（只说「太难了」模型不知道
该改什么）；同时**被解释的词本身不算超纲**——它本来就是学习者不会的词，
不排除掉的话，度量会永远说谎，模型再改也过不了门槛。

**四、卡片带语境。** 生词导出成 Anki 卡片时，背面放的是它出现的那句话，
不是中英对照。

## 现在做到了什么

- 可运行的命令行工具，五个命令：`analyze` / `vocab` / `anki` / `prompt` / `explain`
- **读得进整本 EPUB**：按规范解析容器、清单与阅读顺序，输出逐章体检表
- **真的会调模型**：OpenAI 兼容客户端（默认 DeepSeek），模型的解释先过
  我们自己的可读性审计，不达标就带着更严的约束重试
- 完整的 **HSK 3.0 词表（10,978 词，含拼音）**，附原始数据与许可说明
- **73 个测试全部离线通过**——不需要 API key，不需要网络

用 `samples/sample.epub` 实测，同一本书逐章的判定是真的会变的：

| 章节 | 词数 | 覆盖率 | 判定 |
| --- | --- | --- | --- |
| 第一章 我有一个中国朋友 | 57 | 91.2% | 有点挑战，需要一点支撑 |
| 第二章 茶是一种语言 | 49 | 87.7% | 偏难，建议先降级改写再读 |

复现只要三条命令（第三条需要自己的 API key）：

```bash
moon test
moon run cmd/main -- analyze samples/sample.epub --level 2
moon run cmd/main -- explain 意思 "这句话很有意思。" --word-level 3
```

## 为什么用 MoonBit

- 项目是**文本流水线 + 多后端**的形态：确定性的解析、分词、调度内核用
  MoonBit 写，天然可以同时编到 native 与 wasm-gc，后面做浏览器阅读器
  不需要重写核心。
- 语言自带的 `test` 块、快照测试、`moon fmt`、`moon bench` 让「可测试、
  可复现、可维护」这三件事的成本很低——而它们正是这次比赛要看的。
- 生态里还没有中文分级阅读这一类东西，分词和难度评估都是空白。

## 工程上的三个决定

1. **确定性内核与不确定外壳分离。** 模型调用被压缩成一个 trait，测试里换成
   脚本化的假客户端，所以整条流水线（包括「不达标就重试」这个闸门）都能在
   CI 里离线跑完。
2. **时钟和随机数由调用方传入。** `srs.review(card, grade, today)` 不读系统
   时间，于是「三个月后的复习计划」在测试里可以瞬间验证。
3. **全程不引入浮点。** 覆盖率与难度系数都存千分数，跨后端结果一致，
   快照测试稳定。

## 边界（这一期不做）

- 不做泛用翻译器——翻译不是这个产品的手段
- 不训练、不微调模型
- 不做 App 界面：先在命令行上把正确性和可测试性做扎实，界面是外壳
